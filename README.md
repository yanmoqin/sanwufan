# 三五反线上对战

## 项目目录

`sanwufan/` 是游戏源码，`tests/` 是自动测试，`docs/` 保存完善版规则和远程试玩说明，`deploy/` 保存服务器部署配置，`scripts/` 保存发布包构建工具。Windows 启动文件保留在根目录。

本机最新试玩包位于 `releases/三五反远程试玩包_v0.6.3.zip`；旧包、规则原件、参考项目与开发临时文件归档到 `.archive/`。`runtime/` 是便携运行组件，`data/` 是私人存档。这些本机文件不提交到 GitHub。

规则：[Word 完善版](docs/三五反规则_完善版.docx) · [PDF 完善版](docs/三五反规则_完善版.pdf) · [远程试玩说明](docs/远程试玩说明.md)。

从源码运行需要 Python 3.10 或以上。单人练习可直接执行 `python -m sanwufan.local`；远程试玩先执行 `python -m pip install -r requirements-remote.txt`，再执行 `python -m sanwufan.remote`。便携试玩包包含运行组件，完整解压后可直接双击启动。

牌桌界面更新（2026-10-06）：四个座位、当前出牌、主花色、分数、公开底牌和自己的手牌集中在同一张牌桌。电脑和手机横屏使用横排手牌，手机竖屏使用六列手牌，拿底后的18张牌也能完整显示。点牌后抬起并显示金色选中边框，再按操作按钮提交。

顶部“回看”查看本局已结束的轮次，“菜单”打开玩法、动态、全屏和单人托管；好友桌的“房间”提供邀请、恢复码和离房入口。点分数查看两队详情，点头像进行互动或房主管理，点手牌旁的“特殊牌”查看亮反选择和杠提示。弹层关闭后回到原牌桌，选牌不受影响。四张3或5的推荐亮法直接可选，其他亮法在“其他亮法”中展开。

最新压缩包为 `三五反远程试玩包_v0.6.3.zip`。双击启动文件会打开本机服务管理页，再点“打开牌桌”。打牌时保留管理页；关闭最后一个管理页约15秒后退出本次游戏服务、公网通道和启动窗口。刷新或重复启动会继续使用当前服务，普通玩家关闭牌桌不会停止整桌；管理页也提供“结束本次服务”按钮。未打开管理页的 `--no-browser` 启动保持运行，可按 Ctrl+C 停止。

v0.6.3：尚无人亮主时慢速发牌，有人亮主后立即发完剩余手牌并进入亮反确认。确认只表示可以继续进贡，不关闭亮反；全桌可补亮到庄家扣牌提交前。庄家拿底所得的3、5也能组成反，凑成三张自动亮出，四张时由本人选择亮法。

回看每行显示一轮，纵向滚动即可查看本局已完成的全部出牌；每轮标出领出者、赢家和得分。互动加入从发送者头像飞到接收者头像的抛物线、旋转和击中效果，支持关闭动画及系统减少动态效果设置。

v0.6.1：亮反在头像旁公开显示，并列出实际亮出的三张牌；庄家扣底后全桌可见；支持逐轮回看本局已完成的出牌。单人练习也可点击自动玩家头像互动。发牌间隔为每张0.4秒。

“回看出牌”按轮次显示四家的出牌顺序、牌面、赢家和得分；不会统计各点数剩余牌。进入下一局后清空回看。只有实际亮出的三张牌获得三反、五反等级；四张3中保留未亮的一张仍按普通3使用。主牌大小为方片5 ＞ 五反 ＞ 三反 ＞ 大王 ＞ 小王 ＞ 黑桃Q ＞ 主J ＞ 副J ＞ 主2 ＞ 副2 ＞ 普通主牌。

点击其他玩家头像，可扔鸡蛋、西红柿、送花或鼓掌，间隔3秒，也可关闭互动动画。房主只能在开局前和结算后请离；操作需要确认，会让全桌重新准备，被请离者当前身份在房主重新开桌前不能再加入。已亮的反牌、进贡还贡取得的牌不会被推荐为杠。

首局由服务端自动亮出最先收到的2，后续局手动亮2。手牌发完后，恰好三张3或5自动亮反；四张时由本人选择，推荐三反保留主花色3、五反保留方片5。也可以不亮反，保留四张真杠。拿底后新凑齐三张的反会自动亮出，四张仍需本人选择。特殊牌提示只显示本人手牌；点击杠提示只选牌，不自动出牌。

第六阶段提供一键远程试玩包：Windows 电脑解压后双击启动，自动生成临时 HTTPS 邀请网址，朋友通过浏览器加入。包内自带便携 Python 和 Waitress。规则引擎、四人好友房、SQLite 存档和服务器部署包继续保留；补充个人恢复码，以便临时网址变化后恢复原座位和手牌。

## 运行与验证

在项目根目录执行：

```powershell
python -m sanwufan.web
```

手动执行上述命令后，打开 <http://127.0.0.1:8765>，点击“准备开始”。Windows 可直接双击根目录的 `启动牌桌.cmd`：启动器自动打开浏览器，首选8766端口，占用时自动选择空闲端口；本机独立存档位于 `data/local/games.sqlite3`，保留原有 `data/sanwufan.sqlite3` 和远程存档。重复双击会打开同一牌桌。按 Ctrl+C 停止服务。手动启动时也可用 `--port` 指定端口。

四人好友房入口为 <http://127.0.0.1:8765/friends>。输入昵称创建房间，把六位房间号或邀请链接发给朋友；朋友输入自己的昵称加入。对面是搭档，四人全部准备后自动发牌。未开始的首局可在全部取消准备后换到空座。开局后座位固定，断线保留座位，使用原浏览器回来即可继续。牌局中不自动代打，离线玩家未回来时会等待其操作。

同一浏览器的多个标签页共享一个身份，不能用来扮演四名玩家。请使用各自的设备、独立浏览器或独立浏览器会话。房主可在等待或结算阶段重新开桌；正在打的一局不能被单方清空。等待或结算时可以离房，房主离开后身份顺延给剩余玩家。有人离房时重置本桌比赛和准备状态，新玩家不会继承进贡义务；全员离开后房间关闭。整桌无人访问两小时后过期。

## 同一 Wi-Fi / 局域网联机

只需一台电脑运行服务，朋友直接用手机或电脑浏览器访问，无需各自安装 Python。先在服务电脑执行 `ipconfig`，找到当前 Wi-Fi 或以太网的 IPv4 地址，例如 `192.168.1.23`，再在项目目录执行（替换成实际地址）：

```powershell
python -m sanwufan.web --host 0.0.0.0 --allow-host 192.168.1.23
```

所有人打开 `http://192.168.1.23:8765/friends`，由一人建房，其余人加入。如果 Windows 弹出防火墙提示，为当前私人网络允许 Python；不要关闭整个防火墙。若连接失败，检查双方是否在同一网络、是否使用了正确 IPv4 地址以及路由器是否隔离设备。默认双击启动仍仅监听本机。分享链接应在上述局域网地址打开的页面里复制，`127.0.0.1` 链接只能本机访问。

异地试玩可以双击 `启动远程试玩.cmd`，详见 [远程试玩说明.md](docs/远程试玩说明.md)。临时网址仅在启动通道期间可用，电脑要保持联网和运行；本机好友服务仍使用原存档，远程启动器使用独立存档。好友房默认保存到 `data/sanwufan.sqlite3`，重启同一存档后使用原浏览器回来即可继续；发牌途中恢复时等四位玩家重新连接，再继续发牌。不要用 `--seed` 启动正常好友局，该参数仅用于测试复现。

存档路径可以通过 `--database` 指定，`--no-persist` 只作一次性内存试玩。同一存档只能由一个服务进程使用，重复启动会拒绝打开；存档无效也会拒绝启动并保留原文件，不自动新建空牌局。成功操作先保存再确认，保存失败会回滚并提示重试。房间仍在整桌无访问两小时后过期，停机时间计入。会话 cookie 保留30天，但房间过期、清除 cookie 或更换浏览器后不能自动恢复旧座位。v0.3.0 的旧内存牌桌无法事后恢复，从 v0.4.0 的新房间开始持久化。

部署步骤、在线备份和恢复说明见 [deploy/README.md](deploy/README.md)。部署服务使用一个应用进程，容器数据卷独立保存牌局；应用端口不直接公开，HTTPS 由 Caddy 提供。当前电脑没有 Docker，容器构建和实际证书申请需在选定服务器后验证。

网页支持点选手牌、亮2、亮三五反、进贡还贡、拿底扣底和出牌。“提示”仅选出合法牌组，提交前仍可调整；“托管本局”代你操作到本局结束，途中可以接手。非法操作会显示中文原因并保留手牌；甩牌失败按规则实际领出一张。四张Q领出时可选择真杠或假杠。

刷新页面会恢复同一练习桌。不同浏览器会话各自开桌，同一浏览器的多个标签页共享牌桌；牌局保存在服务进程内，重启服务后重新入座。尚无人亮主时逐张发牌，后续局自动玩家拿到2后稍作等待再亮；亮主成功立即发完剩余手牌。发完48张仍无人亮主时，保留3秒亮2窗口。

命令行演示与测试：

```powershell
python -m sanwufan
python -m sanwufan --deals 5 --seed 7
python -m sanwufan --single-trick
python -m unittest discover -s tests -v
```

默认演示连续三局，自动完成亮2、亮反、进贡还贡、扣底和出牌，打印两队得分、下局庄家及进贡义务。`--seed` 固定演示的洗牌与选牌顺序，方便复现；这些自动玩家用于演示流程，尚未提供策略型 AI。正常开局使用系统随机源洗牌。

自动测试覆盖牌型、跟牌、甩牌、扣底、结算边界、完整流程与 HTTP 会话。好友房测试通过四个独立客户端连续打完三局，检查手牌隔离、刷新恢复、并发过期操作、满员拒绝、座位锁定、房主权限与离房处理；也保留练习桌和规则引擎验证。每个成功牌局操作都会检查54张牌完整且不重复，结束时两队合计100分。

持久化测试覆盖各阶段重启、保存故障回滚、身份和牌面隔离、存档版本校验及在线备份。部署入口的进程测试通过四个独立 HTTP 客户端打到出牌阶段，再直接终止服务，重新启动后检查手牌与版本不变、重复提交被拒绝。完整部署测试先执行 `python -m pip install -r requirements-server.txt`，再运行上述 unittest 命令；不安装部署依赖时，会跳过真实 Waitress 进程测试。

## 完整流程

| 阶段 | 操作与结果 |
| --- | --- |
| 等待准备 | 四个座位全部准备后，由服务器开局 |
| 发牌 | 尚无人亮主时逐张发牌，亮主后立即发完剩余手牌至每人12张；先亮有效者确定主花色，首局同时定庄 |
| 定主补充 | 首局无人亮2进入备用处理；之后无人亮2时，由闲家抽底定主，抽到王重抽 |
| 亮反确认 | 可亮三反、五反；四人确认后判断进贡与免贡，扣牌提交前仍可补亮 |
| 进贡还贡 | 先选最大主牌进贡，再选合法主牌还贡；双贡默认各给自己的下家 |
| 拿底扣底 | 贡牌交换完成或免贡后，庄家拿6张底牌；底牌中的3、5可组成反，再扣6张不带分的牌 |
| 出牌收分 | 庄家首出，依次跟牌，每轮赢家收分并领出下一轮 |
| 本局结算 | 所有手牌打完后，依据闲家得分确定胜负、下局庄家与进贡义务 |
| 下一局 | 保留结算决定，清空本局手牌与主花色；四人重新准备 |

网页在有人亮主时立即完成剩余发牌，不再播放逐张动画或等待最后的亮2窗口。若发完第48张手牌仍无人亮主，允许最后一张2抢亮；练习桌保留3秒，四人好友房保留5秒。服务器通过 `finish_dealing()` 关闭亮2窗口，之后不能改主。

亮反截止于庄家扣牌提交前；确认继续后、进贡还贡时及庄家拿底后都可补亮。庄家从底牌拿到的3、5可以组成反，进贡还贡取得的牌不能组成反。进贡尚未完成时，补亮反产生免贡或导致还贡者没有合法主牌可还，会撤回全部未提交交换。已完成交换后的补亮沿用当前牌桌的晚亮反设置。还贡不能使用已亮出的三反牌，也不能把收到的贡牌原样还回去；任一还贡者没有合法还贡牌时，免除本局全部进贡。方片5可以作为最大主牌进贡。扣底禁止任何5、10、K，允许扣其他主牌、已亮出的2或3及贡牌交换取得的牌。

进贡还贡全部选定后一起提交到服务器手牌，失败的选择不会留下部分交换。各座位的快照会显示自己收到的贡牌与暂时变化的手牌数量。

座位编号为0、1、2、3；0与2一队，1与3一队。下家为 `(seat + 1) % 4`。牌编号为 `S:A`、`H:10`、`C:J`、`D:5`、`J:small`、`J:big`。分值不因亮反改变；亮反只提升实际亮出的三张牌。

```python
from sanwufan import Card, Game, Phase

# 在服务器保存完整状态。
game = Game()
for seat in range(4):
    game = game.ready(seat)
game = game.start_deal()

# 逐张发牌之间接收玩家的亮2请求。
game = game.deal_one()
if game.hands[0][0].rank == "2":
    game = game.call_trump(0, game.hands[0][0])

# 仅把该座位的快照发送给已认证的玩家。
player_view = game.view_for(0)
assert player_view["phase"] == Phase.DEALING.value

# 后续玩家操作示例（仅在对应阶段执行）：
# game = game.reveal(seat, [Card.from_id(x) for x in selected_ids])
# game = game.confirm_declarations(seat)
# game = game.give_tribute(seat, Card.from_id(card_id))
# game = game.return_tribute(seat, Card.from_id(card_id))
# game = game.take_bottom(seat)
# game = game.discard(seat, [Card.from_id(x) for x in selected_ids])
# game = game.play(seat, [Card.from_id(x) for x in selected_ids])
```

`Game` 和 `Trick` 的操作返回新的不可变状态；服务器应在成功后保存返回值。失败会抛出带稳定 `code` 与中文提示的 `RuleViolation`，原状态保持不变。四张Q领出时须显式指定 `PlayKind.TRUE_GANG` 或 `PlayKind.FALSE_GANG`。甩牌失败后实际领出一张，其余所选牌保留在手里。

`view_for(seat)` 返回可直接转换为 JSON 的快照，包含自己的手牌、其他人的张数、亮2与亮反、贡牌交换进度、当前轮与上一轮的公开出牌、真假杠类型、得分与结算。其他座位的手牌、未见底牌和发牌顺序不会出现在快照中；贡牌交换的牌面只对交换双方可见。`revision` 随成功操作递增，可用于同步版本。

完整 `Game` 状态属于服务器私有数据。服务器应从登录身份确定座位并按房间串行处理操作，不能接受客户端自报的任意座位或完整牌局状态。洗牌、发牌、关闭亮2窗口、首局备用定庄等由服务器推进；固定牌序与指定抽底位置供测试复现使用。

## 少见情况的可配置默认值

以下两项暂采用实现默认值，尚未确认是否作为正式牌桌约定：

- 首局无人亮2：重新发牌。可设置为随机定庄，再由闲家抽底定主。
- 进贡还贡完成后才亮反：保留已经完成的交换，仅调整牌的等级。可设置为当亮反方需要进贡时，撤回本局全部贡牌交换。

```python
from sanwufan import FirstNoTrump, Game, GameOptions, LateReflection

game = Game(options=GameOptions(
    first_no_trump=FirstNoTrump.RANDOM_DEALER,
    late_reflection=LateReflection.ROLLBACK_EXCHANGES,
))
```

两种备选处理均有固定案例验证。贡牌交换取得的牌始终不能用于组成三五反或杠。

先通过远程试玩包邀请朋友在各自网络和设备上打完整牌局，收集手机操作与连接稳定性反馈。若需要长期固定网址和电脑关机后仍可玩，再选定服务器和域名，使用已有部署配置。

本阶段通过HTTP轮询同步，操作携带牌桌标识和版本；过期时返回最新状态，不重复执行。服务使用独立会话与房间锁，仅接受当前玩家的动作，发牌、洗牌等由服务推进。正常启动使用系统随机源；可用 `--seed 7` 复现测试牌序。自动玩家执行基本合法选牌，尚未实现策略型AI。
